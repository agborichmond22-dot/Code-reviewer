## 2026-08-09 - Prevent Accidental Code Loss in Code Reviewer
**Learning:** Destructive actions like loading templates or clearing code inputs should conditionally confirm intent with the user only if the editor actually has code to prevent catastrophic loss of user progress. Furthermore, when adding default-parameter handlers (e.g. `clearAll(force = false)`) directly as inline JS event listeners (e.g. `onclick="clearAll()"`), standard browsers pass the implicit click `Event` as the first argument. Since an `Event` object is truthy, a check like `if (!force)` would evaluate to false and bypass the safety confirmation check. Parameters must be strictly verified (e.g. `force === true`) to ensure security/UX logic is robust against unexpected runtime arguments.
**Action:** Always strictly check input arguments and parameter default overrides when bound to browser interaction events, and ensure destructive/clearing actions conditionally prompt the user for validation.
