## 2026-08-05 - Optimizing Keystroke Lag via DOM Throttling & Fast Line Scan
**Learning:** In code editors, executing full DOM updates (such as rebuilding a line-number gutter) and allocating memory (`String.prototype.split('\n')`) on every single keypress causes noticeable UI lag as the document grows. By implementing a cached line count and returning early in O(1) time when the line count hasn't changed, we completely eliminate redundant DOM updates and layout/paint thrashing. Furthermore, scanning for newlines using a low-overhead `indexOf` loop instead of `split('\n')` avoids temporary array allocations, keeping memory usage constant.
**Action:** Always identify keypress-bound event listeners and minimize hot-path DOM writes by caching states, checking parameters strictly to avoid implicit event-object overrides, and utilizing linear substring searches rather than heavy array allocations.
