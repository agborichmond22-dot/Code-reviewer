## 2024-07-29 - [Optimizing Editor Line Gutter Updates]
**Learning:** In the static editor view, calling split('\n') on the entire editor content and rebuilding the gutter DOM elements on every keystroke/input event introduces typing lag. Caching the last known line count and performing an O(1) early return avoids expensive DOM modifications when the line count hasn't changed. Furthermore, an O(N) line counter using index-of searches is significantly faster and doesn't allocate an array, unlike string.split. Finally, when registering callbacks directly as event listeners, the browser's implicit Event object overrides any JavaScript default parameters (e.g., `force = false` becomes the Event object, which is truthy); strict parameter checking (e.g., `force === true`) prevents bypasses.
**Action:** Always cache state transitions and perform early exits before executing expensive rendering or DOM manipulation routines. Use strict type and value checking for event listeners with default parameters.
