## 2026-07-21 - [Gutter Redraw and Allocation Bottleneck on Every Keystroke]
**Learning:** In the custom code editor setup, the `updateGutter` function was triggered synchronously on every single input keypress event. The function split the entire editor text value, allocated a large array of substrings, and performed complete DOM replacement on the gutter element (`gutterEl.innerHTML = ...`). This caused heavy garbage collection and continuous style/layout reflows, which blocked the main thread on larger files. By caching the line count and skipping DOM updates + using regex match for non-allocating line counting when the line count remains unchanged, we achieved O(1) keystroke latency for standard typing.
**Action:** When implementing custom editor line numbers or frequent text event handlers, always cache the structural state (e.g., line counts) and only trigger DOM updates/re-renders or heavy allocation routines (like `split('\n')`) when the structure actually changes.
