## 2025-02-11 - Optimize Line Gutter rendering and event listening
**Learning:** In code editors with a line gutter, updating the DOM and creating array allocations (.split('\n')) on every single keystroke creates significant input lag, especially for larger documents. Comparing the current line count with a cached line count first allows an O(1) early return. Additionally, when registering a callback with default parameters as a JavaScript event listener (e.g. `updateGutter(force = false)`), the browser's implicit `Event` object overrides the default parameter with a truthy value, causing unexpected behavior unless handled with strict type checking (e.g., `force === true`).
**Action:** Use fast non-allocating string searches (like `indexOf`) to count lines, cache the line count, perform early O(1) return if unchanged, and strictly validate default parameters when registering the function directly as an event listener.
