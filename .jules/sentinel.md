## 2026-07-26 - [Secure Client-Side API Key Input and Headers]
**Vulnerability:** Static, hardcoded, or cleartext configuration of Anthropic API keys on the client-side exposes credentials to physical and network-based theft. Direct client-side requests also fail unless headers are properly and securely validated.
**Learning:** For a static client-side frontend, the most secure mechanism to utilize Anthropic APIs without backend proxies is to let the user enter their own key in a masked input of type `password`, store it securely in `localStorage`, and transmit it with exact security headers: `x-api-key`, `anthropic-version`, and `anthropic-dangerous-direct-browser-access: true`.
**Prevention:** Mask user inputs for keys, persist locally inside the browser's `localStorage` under `anthropic_api_key`, strictly validate key presence before making fetch requests to prevent exposing internally leaking stack traces, and enforce direct access authorization headers on client-side fetch.
