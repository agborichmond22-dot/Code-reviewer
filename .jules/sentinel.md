## 2023-11-20 - [Secure Client-Side API Key Persistence and Transmission]
**Vulnerability:** Previously, the frontend web application made direct API requests to the Anthropic Claude API without a user-provided or securely stored API key. Adding client-side API key retrieval/persistence via standard DOM input risks credential exposure if autocomplete, spellcheck, or improper local storage handling is used.
**Learning:** To securely handle API keys entirely in a static client-side application, we must provide a password-masked input (`type="password"`) with `autocomplete="off"` and `spellcheck="false"`, while saving it to `localStorage` safely inside `try/catch` blocks to protect against restricted environments (e.g., iframe sandbox). Direct requests must include `anthropic-dangerous-direct-browser-access: true` with strict CORS and secure HTTP header compliance.
**Prevention:** Avoid plaintext key display, prevent input caching via standard browser mechanisms, and always wrap storage operations to prevent runtime exceptions.
