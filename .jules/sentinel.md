## 2025-03-01 - Client-Side API Key Storage & Handling
**Vulnerability:** Directly exposing hardcoded API keys in client-side applications, or leaking plain-text keys in logs/inputs. Additionally, accessing raw browser APIs like `localStorage` without a fallback mechanism can lead to application failure in restricted environments.
**Learning:** Client-side static applications should never hardcode secrets. If client-side requests must be made directly (e.g. to Anthropic API), the user must supply their own API key via a password-masked UI input, which is securely persisted in `localStorage` under a try/catch block to prevent uncaught DOMExceptions in privacy-restricted browser contexts.
**Prevention:** Always use password-masked inputs for user-supplied credentials, avoid hardcoding keys, use strict error handling with a safe fallback when accessing Web Storage APIs, and include proper direct browser access headers like `anthropic-dangerous-direct-browser-access: true`.
