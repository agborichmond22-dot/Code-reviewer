## 2024-07-20 - Secure Key Input and Browser API Call Header Configuration
**Vulnerability:** The application was initially set up to perform client-side AI code reviews via the Anthropic Claude API but lacked any secure mechanism or UI input to enter or handle the Anthropic API key safely, forcing hardcoded key usage or failing with HTTP requests due to missing essential security headers.
**Learning:** For client-side API requests directly to Anthropic, the API requires specific headers including `x-api-key`, `anthropic-version`, and a crucial opt-in header `anthropic-dangerous-direct-browser-access: true`. Without this, the browser CORS configuration would fail, while also posing severe credential leakage risks if hardcoded.
**Prevention:** Implement a password-masked UI input to let users input their own API key, securely persisting it in the browser's local storage (`localStorage`) instead of any server-side or hardcoded location, and dynamically pass the correct browser-access opt-in header with client-side fetch requests.
