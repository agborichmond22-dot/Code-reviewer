## 2026-08-11 - Secure Client-Side API Key Storage
**Vulnerability:** Static, frontend-only web applications that directly call third-party APIs (like the Anthropic API) must not hardcode keys or expose them in git repositories, but instead require the user to input their own keys. If keys are entered via plain text fields, they can easily be read over the shoulder or exposed, and storing/retrieving them from localStorage without safety checks can lead to application crashes (e.g., inside restricted browser/sandbox environments where localStorage is disabled or restricted).
**Learning:** Hardcoded keys are a primary source of severe security leaks in static apps. Using a password-masked input (`type="password"`) with `autocomplete="off"` and `spellcheck="false"` secures the key visually. Safely reading/writing to/from local storage inside `try-catch` blocks ensures that the app fails gracefully or runs correctly even if browser local storage permissions are disabled.
**Prevention:** Always implement password-masked key configuration fields, avoid hardcoded keys, disable autocomplete/spellcheck on secret inputs, and wrap all client-side localStorage transactions in robust error handlers.
