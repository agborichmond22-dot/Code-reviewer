## 2026-08-09 - Secure Client-Side API Key Persistence and Integration
**Vulnerability:** Lack of user-supplied third-party API key mechanism, causing either a functional gap or potential hardcoding of secrets, coupled with exposing keys in browser autocomplete history or input fields.
**Learning:** For static, serverless client-side web applications that consume third-party AI APIs directly from the browser, secrets must never be hardcoded. They must be collected dynamically from the user, input-masked with `type="password"`, `autocomplete="off"`, and `spellcheck="false"`, and sent over safe headers like `x-api-key` and `anthropic-dangerous-direct-browser-access: true`. Local storage operations must be robustly wrapped in `try/catch` blocks to prevent unhandled `DOMException` errors in environments with strict sandbox/privacy configurations.
**Prevention:** Mask all sensitive credential fields, disable browser autocomplete and spellcheck cache, and wrap client-side persistence layers in error boundaries while utilizing vendor-mandated direct-access security headers.
