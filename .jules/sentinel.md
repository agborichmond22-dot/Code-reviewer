## 2024-08-07 - Secure API Key Input Management in Client-Side Apps
**Vulnerability:** Client-side applications often lack standard password-masked input fields for API keys, causing users to accidentally expose keys during screen shares or in browser auto-fills. Additionally, loading and saving `localStorage` variables without safe handling can crash application execution in restricted or cookie-blocked browser sandboxes.
**Learning:** Adding a password-masked HTML input with `autocomplete="off"` and `spellcheck="false"` significantly reduces the risk of accidental exposure. In direct browser-to-API requests to Anthropic's Claude API, headers like `anthropic-dangerous-direct-browser-access` must be explicit, and API keys must be retrieved safely from dynamic UI bindings rather than static config files.
**Prevention:** Always mask user-supplied credentials/tokens using `<input type="password">`, prevent browser caching/spellcheck on sensitive elements, and safely catch any `DOMException` related to disabled `localStorage` operations.
